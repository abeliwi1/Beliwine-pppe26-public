Down a Column

The same 8×8 array, read two ways. One of them asks the memory system for eight times as much work — and the array never moves.

step 0 / 8

How you picture it

a[row][col] — 8 rows, 8 columns of double

Where it actually is

One flat run of memory, row after row. The dashed boxes are 64-byte cache lines — eight doubles each. Memory is fetched a whole line at a time, never one element.

Same eight numbers, same arithmetic. Reading across a row, one fetched line answers all eight requests. Reading down a column, every element lands in a different line, so eight lines come in and seven eighths of every one is thrown away untouched.

That is the whole of loop interchange: swap the two loops so the inner one runs along the direction memory is laid out in. Nothing else about the program changes.

In the course examples this is a 4096×4096 matrix, where one row is 32 KB and a column step jumps that far every time. Measured on a Ryzen AI 9 HX 370: 67.2 ms down columns, 10.7 ms along rows — 6.3×, with identical results to the last bit.
