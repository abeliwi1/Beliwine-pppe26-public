Out of Registers

A processor has a fixed number of registers. Ask a loop body to keep more values alive than that, and the compiler starts parking the overflow in memory — paying a load and a store, every value, every iteration.

What you are looking at

The kernel computes 32 cross-correlations of one signal against 32 reference vectors. Splitting that one wide loop into several narrower ones is loop fission, and the buttons choose how wide each piece is.

Each slot is one architectural register. x86-64 gives you 16 xmm registers for floating point and 16 general-purpose ones, of which about 15 are usable — %rsp is the stack pointer and is spoken for.

The loop body has to keep alive one accumulator per correlation, one pointer per reference vector, plus the signal pointer, the loop counter, and the current sample. At 32 correlations that is 67 values competing for 31 slots.

The compiler does not really assign accumulator k to register k — it allocates registers globally and evicts whatever it judges least valuable. But the counting argument holds regardless: more live values than registers means something goes to memory.

Note that the chips above count values with nowhere to live, while the counter beside them counts instructions that touch the stack. One spilled value costs more than one instruction — at minimum a store and a reload each time round the loop — which is why the instruction count runs well ahead of the overflow count.

What it costs, in the actual assembly

A spilled accumulator is written to a stack slot and read back inside the hot loop, on every iteration:

; one spilled accumulator, 32-accumulator version
movss   %xmm1, -52(%rsp)     ; park it in memory
...
addss   -52(%rsp), %xmm15   ; fetch it back to accumulate

Count those and you have measured the problem directly. grep -c '(%rsp)' on the generated assembly turns the whole question into an observation — and the speedup tracks the count exactly.

The curve bends exactly where the spills reach zero. Splitting further buys nothing measurable — there is nothing left to remove, and eight passes over the signal instead of four cancel the rest.

Two things worth taking away

Sixteen accumulators is not enough here, and the breakdown says why. At 16 only 12 of the 57 stack references are spilled accumulators; the other 45 are spilled pointers. Sixteen accumulators nearly fit the 16 xmm registers, and in doing so they squeeze the reference pointers out of the general-purpose file instead. The pressure moved rather than disappeared.

The right split is a property of the chip, not the algorithm. On an instruction set with 32 floating-point registers, 16 accumulators per loop would fit and the half-split would be correct. Re-measure whenever you change targets.
