Bitmap Join

How libc++'s std::sort partitions without a single branch on the data. It compares a block of elements from each end against the pivot, records the answers as bits, then pairs the bits up to decide which elements to swap. This is the BlockQuicksort scheme of Edelkamp and Weiß, implemented as __bitset_partition in <__algorithm/sort.h>.

The real blocks are 64 elements, one per bit of a uint64_t. The figures shrink them to 8 so every bit is visible. The left block runs forward from first; the right block runs backward from lm1 (last − 1), so bit j on the right is the element j places in from the end.

Step 2: the join

Each set bit on the left needs a partner from the right to trade places with. The join pairs them in order: the lowest set bit on the left with the lowest set bit on the right, then the next pair, until one bitset runs out. This is __swap_bitmap_pos:

while (left != 0 && right != 0) {
    int l = ctz(left);   left  = blsr(left);    // ctz: index of lowest set bit
    int r = ctz(right);  right = blsr(right);   // blsr: clear lowest set bit, x & (x - 1)
    swap(first[l], lm1[-r]);
}
first += (left  == 0) ? 64 : 0;   // a side advances only when its block is used up
lm1   -= (right == 0) ? 64 : 0;

Why it beats a Hoare partition

  • Hoare branches on every comparison: scan until an element is on the wrong side, stop, swap. On random data each of those branches is close to a coin flip, so about half of them mispredict.
  • The bitmap version separates deciding from moving. The compare loop has no data-dependent branch. The join loop's only branch is "are both bitsets non-empty?", which depends on how many bits are set, not on any single comparison, so it costs about one mispredict per block, not one per element.
  • The price is extra work: every element is compared and written into a bit even when it is already on the right side, and each swap needs ctz and blsr. ARM64 has no single ctz instruction, so it takes rbit plus clz. Lecture 08 measures the trade as a large win: the branch-free partition is why clang's std::sort is about 3x faster than GCC's at a million elements.

Two details are left out of the figures. Before the block loop, the pivot is moved to first and two short unguarded scans skip the elements already in place. After it, fewer than two blocks remain; __bitset_partition_partial_blocks fills partial bitsets, and __swap_bitmap_pos_within moves any leftover marked elements to the middle. libc++ uses this partition only for arithmetic types sorted with a comparator it knows is branch-free, such as the default std::less.
