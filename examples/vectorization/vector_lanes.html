One Instruction, Many Lanes

A vector register is an ordinary register that the hardware has agreed to read as several numbers side by side. How many depends on two things, and you control both.

What you are looking at

Both rows compute exactly the same thing: for each position, is a equal to b? A lane that matches fills with all ones, which is how a vector compare reports true; a lane that does not is left at zero.

The scalar row does it one position per instruction, so it needs as many instructions as there are elements. The vector row does every position in one. That is the whole idea, and the only number that changes it is the lane count.

Lanes are the ceiling

Lane count is just division:

lanes = register width ÷ element width

Which means the data type you pick changes your speedup. Switch the element from int32 to int64 above and watch the lane count halve — same register, same instruction, half the work per issue. No transformation in the loop-optimization lecture behaves that way.

These are ceilings, not speedups. You will not reach them — loads, stores, the leftover elements at the end of an array, and anything that moves data between vector and scalar registers all cost. But the lane count tells you immediately whether a rewrite is worth attempting, and a 512-bit register is four times the width of a 128-bit one without being four times the speed.
