# Branch Optimizations

Learning goals:
  * Understand what a branch costs when it cannot be predicted
    * speculation, pipeline flush, ~15-20 cycles per miss
  * Know the branchless transformations, and where they are actually needed
    * signed-shift masks, branchless min/max, comparison-as-integer
    * on this machine the compiler emits `csel` and you rarely write them —
      but SIMD lanes, GPUs and in-order cores have no `csel` to rescue you
  * Recognize the two shapes of "the compiler will not do this"
    * it cannot **derive** the transformation (lookup tables)
    * it cannot **prove** the transformation is legal (aliasing)

## Where this picks up from Lecture 03

Lecture 03 measured what a mispredicted branch costs: sorted vs. shuffled data
over identical code, an order of magnitude apart, with the whole difference
showing up as CPI. That was the hardware's side of the story.

This lecture is the programmer's side — what you do about a branch once you
know it is expensive. Three answers, and only one of them is a technique you
will reach for on this machine:

1. **Remove the branch with arithmetic.** Clang already does this for you at
   `-O1`; the hand-written version compiles to identical code. Learn it anyway,
   because it is the only option on hardware without conditional select.
2. **Replace the computation with a table.** Worth it only when the table entry
   costs more than the compiler can fold — a CRC round, not a two-way select.
3. **Hoist a condition the compiler is not allowed to hoist.** When the test is
   read through a pointer that might alias the output, invariance is unprovable
   and the loop never vectorizes. One line fixes it.

The through-line: an optimizer declining to do something is not one situation.
It may have already done better than you would, it may lack a derivation, or it
may lack a proof. Only the last two are work for you.
