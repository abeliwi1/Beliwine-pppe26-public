# Instruction-Level Parallelism: Out-of-Order and Speculative Execution

Learning goals:
  * Understand instruction-level parallelism as parallelism *without* concurrency
    * one instruction stream, several instructions in flight
    * the four mechanisms: pipelining, out-of-order issue, speculation, SIMD
  * Measure throughput with CPI/IPC
    * why CPI < 1 is possible and what it tells you
    * why CPI stops being informative once you are bandwidth-bound
  * Understand the reorder buffer (ROB) and what limits it
    * the data dependency graph, not program order
    * the ROB is *near-sighted*, not blocked — window size vs. distance
  * Understand branch prediction and the cost of a wrong guess
    * why data order changes performance with code held constant
    * branchless code as a trade, not a free win

## Where this picks up from Lecture 01

Lecture 01 established that a processor overlaps instructions in a pipeline,
and that a RAW hazard stalls that pipeline: if instruction B needs a value
instruction A hasn't finished computing, B waits. We fixed those stalls by
restructuring code — independent chains, multiple accumulators, CSE — so the
pipeline always had something useful to do.

That was the *static* picture: a fixed sequence of instructions flowing
through fixed stages. Real cores are more aggressive than that. They don't
execute in the order you wrote; they execute in the order the data allows.
This lecture is about the hardware that makes that decision, what you can do
to help it, and — importantly — what it cannot do for you no matter how
helpful you are.
